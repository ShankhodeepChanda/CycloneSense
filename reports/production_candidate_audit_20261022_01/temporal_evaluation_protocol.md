# Future temporal evaluation protocol for 2024+ data

**Status checked 2026-10-22.** The local raw IBTrACS cache contains 2024+ track records, but none of the repository's `images_index.csv` files contains a paired IR chip after 2023. This protocol is for a later evaluation once source imagery is retrieved and validated. No images were downloaded for this audit.

## Data source and provenance

1. Keep IBTrACS v04r01 as the track-label source and record the exact source URL, access date, file SHA-256, version, and local snapshot. IBTrACS provides global storm positions and intensity; its documentation notes different agencies and wind averaging periods. For every retained row, preserve `USA_WIND`, `USA_AGENCY`, `USA_STATUS`, `WMO_WIND`, `WMO_AGENCY`, `IFLAG`, `TRACK_TYPE`, SID, UTC time, position, and the chosen wind-field rationale. The current chip index retains `wind_kt` but omits row-level agency provenance, so future indexes should retain it.
2. For backward-compatible images, continue the current daily NASA GIBS MODIS Terra/Aqua Band 31 daytime layers. Record the layer name, product version, GIBS request parameters, date, center latitude/longitude, image dimensions, source-file hash, rendering/palette, and attribution. GIBS metadata identifies Band 31 brightness temperature as a daily layer tied to MODIS calibrated-radiance products; the current builder saves a palette-rendered 256×256 RGB chip as JPEG, not raw calibrated radiance.
3. Use the same label-to-pass rule as the current builder: select the nearest daytime local overpass for each storm and satellite, assign the closest eligible IBTrACS main-track record within ±3 hours, and retain the exact UTC timestamp, pass date, and signed `offset_h`. Keep the 10° chip, 256-pixel image, `valid_fraction >= 0.6`, RGB conversion, and JPEG quality 90 only if those choices are deliberately frozen for comparability. Recheck collisions, missing rows, image bounds, valid fraction, and time offset before accepting the new index.
4. Recompute category from the frozen thresholds (TD <34 kt; TS 34–63; C1 64–82; C2 83–95; C3 96–112; C4 113–136; C5 ≥137). Check category against the stored source value. Review `USA_AGENCY`/`IFLAG`, agency-specific wind conventions, provisional/reanalysis status, suspicious discontinuities, and any difference from WMO wind before accepting a high-intensity label. Keep both source wind fields; do not silently substitute one for another.
5. Do not mix GOES ABI, Meteosat, or another sensor into the current MODIS RGB training domain without a separate channel/projection/calibration/preprocessing definition and sensor-stratified validation. NOAA GOES ABI offers public Level-1b radiances, but coverage is the Americas and the data are native NetCDF radiances. EUMETSAT archives Meteosat imagery back to 1981, with product-specific access/licensing; verify the exact product licence before use or redistribution.

## Split and evaluation design

- Freeze an event-level split manifest by SID before reading model results. Any eligible storm with a best-track year in 2024 or later goes wholly into the future temporal holdout. Do not hash those storms into train/validation or split images from one SID across partitions. Keep all existing 2018–2020 train/validation/test and 2021–2023 temporal assignments unchanged.
- For inference-only assessment of the current production candidate, use its existing frozen weights on 2024+ images after the label/image checks. For future training experiments, choose train and validation storms from the permitted pre-holdout years (for example 2018–2023, with storm-disjoint grouping), select checkpoints and settings on validation only, and keep every 2024+ storm sealed. Maintain the original augmentation strategy (`RandomResizedCrop` scale 0.8–1.0 plus ±30° rotation; no horizontal flip) in any such experiment.
- The current `scripts/build_temporal_test.py` is hard-coded to 2021–2023 and selects the five storms per year with the most planned image jobs. A future 2024+ builder should use a separate output directory and manifest, use all eligible storms or pre-register a label-independent sampling rule, and must not select storms based on prediction errors. The evaluator should assert year bounds, label completeness, and zero SID overlap with training/validation.
- Freeze the primary checkpoint and its digest: `models/multiyear45_resnet18_ir_weighted.pt` (ResNet-18, one unconstrained regression output, IR, target `wind_kt/100`). Record the SHA-256, source code revision, Python/PyTorch/torchvision/Pillow versions, device, resize/interpolation settings, normalization constants, batch/order policy, and prediction CSV hash. Use `Resize(224) → RGB → ToTensor → ImageNet Normalize([0.485,0.456,0.406], [0.229,0.224,0.225])`; convert raw output to knots by multiplying by 100. Do not retrain or replace this frozen baseline.
- Freeze the baseline alongside it: (a) the current production candidate and (b) a constant training-mean wind baseline computed only from the frozen training labels. The existing weighted temporal report records that mean as 49.363 kt for the current training set. Recompute a mean only for a separately documented future-training comparison; never use holdout labels to set it.
- Save raw, unclipped predictions. If the application requires nonnegative displayed wind, create a separate display field `max(raw_prediction_kt, 0)` and retain both values; compute research metrics from raw outputs unless a distinct clipped metric is clearly labeled and reported in parallel.
- Report image-level MAE, RMSE, mean bias, median absolute error, category accuracy, and within-one-category accuracy; report per-storm MAE/bias and the unweighted mean across storms; report per-category image and independent-storm counts, MAE, RMSE, bias, and extreme errors. Include per-year and Terra/Aqua summaries. Show C4/C5 counts and mark estimates with fewer than 10 images or fewer than 5 storms as low-sample. Use paired bootstrap resampling at the SID level for uncertainty, never by image.
- Once predictions have been written and the evaluation configuration is frozen, publish the manifest, source provenance, prediction file, metrics, and report together. Do not tune on this holdout. If any model or preprocessing choice changes after seeing these results, reserve a later untouched temporal period for the next evaluation.

## Official source notes

- [NOAA NCEI IBTrACS overview](https://www.ncei.noaa.gov/metadata/geoportal/rest/metadata/item/gov.noaa.ncdc:C01552/html) describes global track/intensity coverage and cautions that agency reporting practices differ.
- [IBTrACS v04 column documentation](https://www.ncei.noaa.gov/sites/default/files/2021-07/IBTrACS_v04_column_documentation.pdf) defines wind fields, track type, and agency-dependent averaging periods. Preserve source agency fields when building new indexes.
- [NASA GIBS Terra Band 31 layer metadata](https://gibs.earthdata.nasa.gov/layer-metadata/v1.0/MODIS_Terra_Brightness_Temp_Band31_Day.json) and [Aqua layer metadata](https://gibs.earthdata.nasa.gov/layer-metadata/v1.0/MODIS_Aqua_Brightness_Temp_Band31_Day.json) identify the daily Band 31 brightness-temperature layers and corresponding MODIS radiance products. [NASA Earthdata use guidance](https://www.earthdata.nasa.gov/engage/open-data-services-software/data-use-policy) asks users to check product-specific restrictions, cite datasets, and acknowledge NASA.
- [NOAA GOES open-data listing](https://registry.opendata.aws/noaa-goes/) documents public access and use terms, available files, and geographic coverage.
- [EUMETSAT data policy](https://www.eumetsat.int/legal-framework/data-policy) and [data access portal](https://user.eumetsat.int/data-access?l=en) describe archived data and product-specific access/licensing. Confirm licensing for the chosen product before use.
